# Agent Manifest Public Registry

This repository contains the public registry of declared Agent Manifests.

**`registry.json` is the authoritative, machine-generated index.** This Markdown
file is a human-readable convenience listing derived from it; if the two ever
disagree, `registry.json` is the source of truth.

Machine-readable index: [`registry.json`](registry.json)

---

## The `registry.json` contract

`registry.json` is generated by [`scripts/generate-registry.py`](scripts/generate-registry.py)
from what is committed in this repository. Running it on the same commit
produces the same file, except for `generated_at`.

| Field | Meaning |
|---|---|
| `registry_version` | Version of **this file's** data contract. Currently `1.1` |
| `generated_at` | When the file was last generated |
| `base_url` | The base a `manifest_path` resolves against, published so that the paths are usable from outside this repository |
| `agents` | Every manifest path, sorted. Unchanged since `1.0` |
| `index` | One entry per manifest that declares an `agent_id` |

Each `index` entry carries exactly the five fields the discovery layer already
documented as registry output — `agent_id`, `manifest_path`, `manifest_url`,
`registered_at`, `source` — and no others.

### Three things worth stating plainly

**`index` is an array, not an object keyed by `agent_id`.** Nothing in this
ecosystem declares `agent_id` unique: the schema pattern is
`^[a-zA-Z0-9._-]+$`, with no namespace and no issuing authority. A lookup by id
can therefore return zero, one or several entries, and the shape has to be able
to say so rather than quietly picking one. A reader that assumes at most one
entry is making a promise this registry cannot keep.

**`registered_at` is what the registry did, not what the operator said.** It is
the author date of the commit that added the file, so anyone can reproduce it
from public git history. It is deliberately **not** the manifest's own
`declaration_date`, which is a self-declared value. Where the date cannot be
derived, the field is omitted rather than guessed.

**`registry_version` here is not the `registry_version` in the discovery
document.** Two independent contracts happen to share a field name: this one
versions the shape of `registry.json`; the one in
`/.well-known/agent-manifest-registry.json` versions the shape of that discovery
document. They move independently and a change to one says nothing about the
other.

### What changed in 1.1, and what did not

`base_url` and `index` were added. `agents` is untouched, so a reader written
against `1.0` keeps working without changes. The bump is additive and breaks
nothing.

### What the index is not

Inclusion records that a declaration was submitted and appended. It is not
endorsement, not verification, not a statement that the declaring system behaves
as declared, and not an ordering of any kind. Entries are sorted by `agent_id`
so that the file is stable across regenerations — never by any property of the
manifest, because sorting by a property is ranking under another name.

## How to register a new Agent Manifest

1. Open a new issue in this repository.
2. Use the **Manifest submission** template.
3. Paste the Agent Manifest JSON.
4. The registry will update automatically.

---

## Notes

The registry is:

- public
- automatically generated (`registry.json`)
- auditable

Every entry validates against the published Agent Manifest v1.0 JSON Schema:
https://agent-manifest-spec.org/spec/v1.0/schema.json
